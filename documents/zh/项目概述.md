# 项目概述 - CS6290 小组项目：Polymarket 信号分析

**日期**：2026-03-23

**状态**：**更新版** 

## 1. 项目概述 (Project Overview)

### 核心选题

Polymarket Signal Analysis — Empirical Detection of Unusual Market Stress Events and Sniper Attacks.

### 核心形态

一个基于 Web 的**静态分析展示页 (Static Analytical Showcase)**。 项目组将在后台离线运行数据管道，生成特定市场的"异常事件"数据集。最终交付物是一个无需后端实时支持的网页，用于交互式地展示检测结果和统计佐证。

## 2. 目标与非目标 (Goals & Non-Goals)

### 2.1 目标 (Goals)

- **核心目标**：实现一套离线算法流程，能够输入历史数据，输出"异常事件"列表。
- **展示目标**：构建一个前端界面，清晰地将"市场异常"与"统计佐证"（如压力分数、成交量激增和狙击手攻击模式）对应展示。
- **工程目标**：
  - 实现数据清洗与重采样（Resampling）机制。
  - 实现两类特定的异常检测算法，**展示其因果关系**：
    - **原因（微观层面）：狙击手攻击检测**。通过基于会话的分析识别特定的可疑钱包行为来追踪根本原因。
    - **症状（宏观层面）：市场层面压力异常检测**。检测由异常活动导致的可观察市场干扰。

### 2.2 非目标 (Non-Goals)

- **不做实时**：演示时不连接 Polymarket 实时 API，不进行实时监控。
- **不做交易**：不提供买卖建议，不连接钱包。
- **不做复杂归因**：不尝试解释"为什么"发生异常（如不抓取外部新闻），只展示"发生了什么"。

## 3. 核心展示策略 (Core Display Strategy)

鉴于展示页的静态性质和浏览器性能限制，我们将在 Streamlit 中采用**"侦探报告"卡片式 UI（钻取交互）**来直观展示两个异常维度之间的因果联系：

- **第 1 级：宏观证据**：卡片初始显示宏观层面症状（例如分钟级压力分数激增或极端流动性变化）。
- **第 2 级：微观追踪**：用户可以展开卡片以揭示微观层面的根本原因，显示特定的可疑钱包地址、其异常分数以及狙击手攻击的确切序列（例如大额快速买卖对）。

## 4. 核心项目流程 (Project Pipeline & User Flows)

本项目的数据流向被严格划分为三个阶段：

### 阶段一：数据获取与预处理 (Data Acquisition & Preprocessing)

*目标：构建标准化的、时间对齐的历史数据集。*

1. **获取 (Ingest)**:
   - 脚本调用 Polymarket API (CLOB/History) 拉取指定市场（如 "US Election 2024"）的原始交易数据和时间序列/快照数据。
   - 获取包含时间戳、大小/金额、价格和钱包地址信息的交易数据。
   - 获取包含中点价格、点差、深度和失衡信息的时间序列/快照数据。
2. **清洗与对齐 (Clean & Align)**:
   - **填补缺失值**: 处理 API 返回的空洞。
   - **时间对齐 (Time Alignment)**: 确保交易数据和时间序列数据在相同的时间戳上对齐（Resampling 到统一的分钟级），以便后续分析。

### 阶段二：算法检测 (Algorithmic Detection)

*目标：运行离线算法，输出异常事件列表。我们将重点检测两类模式：*

1. **模式 A：市场层面压力异常检测**
   - **定义**: 通过对聚合交易和市场状态数据的统计分析来检测异常市场行为。
   - **检测逻辑**:
     - 将交易数据聚合到固定时间桶中（例如 60 秒）。
     - 将时间序列/快照数据聚合到相同的时间桶中。
     - 融合交易特征和快照特征。
     - 计算多个维度（交易活跃度、流动性、价格行为）的滚动 z-分数。
     - 计算综合压力分数并识别异常时间桶。
     - 将连续的异常桶合并为压力事件。
     - 用额外的市场状态信息丰富事件并归因主导驱动因素。
   - **输出**: 标记为 "Type A: Market Stress Anomaly"。
2. **模式 B：狙击手攻击检测**
   - **定义**: 检测操纵行为，攻击者使用大额资金执行快速买卖序列，持有期极短。
   - **检测逻辑**:
     - 使用基于会话的分析（同一地址在短时间窗口内的交易）。
     - 应用带有嵌入交易序列的异常检测。
     - 识别具有特定狙击手特征的顶级异常会话（大额交易 + 先买后卖 + 极短持有 + 2 笔交易）。
   - **输出**: 标记为 "Type B: Sniper Attack"。

### 阶段三：结果展示 (Result Showcase)

*目标：用户在 Web 界面查看阶段二生成的分析结果。*

1. **全局概览 (Global Overview)**:
   - 用户打开网页，看到全量时间轴的市场压力事件。
   - 时间轴上用不同颜色标记了 **Type A (市场压力异常)** 和 **Type B (狙击手攻击)** 异常点。
2. **交互下钻 (Interactive Drill-down)**:
   - 用户点击一个 **Type A** 标记 -> 弹窗展示该事件期间的压力分数组件、流动性变化和价格行为（证明市场压力）。
   - 用户点击一个 **Type B** 标记 -> 弹窗展示交易序列、钱包地址和攻击窗口可视化（证明狙击手攻击模式）。

## 5. 关键决策与风险管理 (Key Decisions & Risk Management)

### 5.1 已识别的风险 (Identified Risks) & 缓解策略 (Mitigation Strategies)

| 风险点                             | 描述                                                         | 缓解策略 (Mitigation)                                        |
| ---------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **数据不可用 (Data Unavailability)** | 狙击手攻击检测需要钱包地址信息，当前数据源可能不包含这些信息。 | **数据源扩展**。从 Polymarket API 或区块链浏览器获取包含钱包地址的原始交易数据，以支持基于会话的分析。 |
| **浏览器性能瓶颈 (Browser Performance Bottleneck)** | 直接加载大量高频数据会让浏览器崩溃。                      | **按需加载**。前端默认只加载聚合概览数据；只有用户点击特定事件时，才加载该事件的详细数据。 |
| **算法"事后诸葛亮" (Algorithm "Hindsight Bias")** | 预计算结果可能看起来像是人工挑选的。                         | 在界面上**明确展示算法阈值**（如："检测阈值：前 5% 压力分数"），表明这是基于规则的客观筛选。 |

### 5.2 技术栈 (Tech Stack)

- **数据处理**: Python (Pandas, NumPy, Scikit-learn)
- **数据源**: Polymarket Clob API / Historical Data Snapshots
- **前端展示**: Streamlit
- **数据格式**: Static JSON files

## 6. 项目结构 (Project Structure)

项目组织为三个主要子模块：

1. **algorithm**: 包含异常检测的核心算法实现：
   - **CS6290-polymarket-anomaly-detection**: 用于识别异常市场压力事件的市场压力检测管道。
   - **sniper_detection**: 用于识别可疑钱包行为的狙击手攻击检测模块。

2. **data**: 包含数据收集和存储组件：
   - **pet-getdata**: 用于获取和处理 Polymarket 数据的脚本。
   - **polymarket_data**: 存储历史交易和时间序列数据。

3. **visualize**: 包含用于显示检测结果的前端组件：
   - **frontend_sniper_detection**: 狙击手攻击案例的可视化组件。
   - **app.py**: 用于结果展示的主 Streamlit 应用。
